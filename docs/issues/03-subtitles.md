## S01 字幕选择参数校验

**优先级：中。**

### 已确认的现状

[`render-film.mjs`](../../production/mv/render-film.mjs) 中 `which === 'bilingual' ? ... : ...` 将所有其他值映射到日文输入，字幕输出后缀却仍使用用户传入字符串；这不只是提示缺失，还可能把日文内容写到误导性的语言后缀。该分支在视频编码完成后执行，错误的资源选择也可能到长渲染后才暴露。

### 实现与验收

- [ ] 仅接受当前确实支持的 `ja`、`bilingual`；不传 `--srt` 则不导出字幕。拒绝非法值、缺失参数值和把下一个旗标误读成值的情况。
- [ ] 在启动编码前校验所选值，非法值给出 REFUSED、合法值列表及非零退出码；dry-run 同样校验。
- [ ] 编码前明确所选字幕源。真实字幕输出应提前检查可读取性，避免做完整视频后才发现字幕不存在；dry-run 可以只报告缺失，不要求补齐歌词。
- [ ] 用 `ja`、`bilingual`、`zh`、`japanese`、缺值和未设置等用例验证；非法值不能回退成日文，也不能启动编码或留下伪成功报告。

## S02 字幕按输出区间裁剪

**优先级：中。**

### 已确认的现状

`writeShiftedSrt()` 只减去偏移并过滤 `end <= 0`，写出时夹住负时间，没有视频尾端裁剪。局部导出可能包含晚于视频结束的条目。返回的 `firstStart` 也可能与实际被夹至零的写出结果不一致。

### 实现要求

- [ ] 裁剪窗口使用实际输出区间：歌曲时钟 `[AUDIO_SEEK, AUDIO_SEEK + n / fps)`。不要把 source PTS 直接当作歌词时间。
- [ ] 平移后把相交条目裁剪至 `[0, n / fps]`；删除完全在窗口外的条目，保留交界处的正确相交部分。
- [ ] 毫秒舍入后再排除零长、负长条目，重新连续编号。可表示的尾端按一致的毫秒策略限制，避免浮点误差造出越界字幕。
- [ ] 对整片同样使用实际输出时长约束，保持无额外 64ms 全片平移。
- [ ] 记录输入条目数、输出条目数、删除与截断数量，以及实际写出的首尾时间；不要只增加计数却不修复越界。

### 验收

使用自行编写的合成 SRT 覆盖：完全在片段之前/之后、跨起点、跨终点、包围整个片段、恰好贴边、多行文本、舍入成零长。以 12 秒局部输出为例，所有写出条目须满足 `0 <= start < end <= 12s`，编号连续，报告与文件一致。

## S03 时间基准与字幕偏移可见性

**优先级：中低；属于可观测性改进，不是已证实的同步算法错误。**

### 现有契约

当前默认参数下：

| 请求 | 参数时间基准 | 实际音轨起点 / 字幕减去的偏移 | 帧数（60fps） |
| --- | --- | --- | --- |
| `--output-range 44 56` | 歌曲输出时间 | 44 秒 | 720 |
| `--range 44 56` | source PTS | 44.064 秒 | 721 |

两者不是同一片段，差异来自现有时钟和区间端点契约。当前 dry-run 已有 `audioSeekSeconds` 及首尾 source PTS，但没有独立字幕规划字段。64ms 不是所有参数下都固定存在的字幕错误；`--audio-offset` 可以改变映射，输出范围也会量化到帧网格。

### 实现与验收

- [ ] 保留两套接口的现有语义，不把两个偏移强行设为相同，也不对歌曲时钟字幕额外叠加一次画面偏移。
- [ ] 开始编码前显示实际输入时钟、音轨 seek、字幕 shift、输出时长；未请求字幕时标明禁用。
- [ ] dry-run 与旁车提供结构化 `subtitles` 规划，建议包含 `enabled`、`language`、`source`、`shiftSeconds`、`durationSeconds` 及区间基准。裁剪统计只有读取并解析后才可填，未计算时不能伪报零。
- [ ] 仅字幕、无音轨的 `--no-audio --srt ...` 组合仍按所选片段对应的歌曲时间平移；禁用声音不等于把字幕 shift 归零。
- [ ] 默认参数验证表中两个示例，再覆盖整片、其他 offset、非整帧边界；字幕 shift 必须与该片段实际使用的歌曲时钟一致。验证精度应考虑 SRT 的毫秒表示，不能把舍入误差混同于时钟错误。
