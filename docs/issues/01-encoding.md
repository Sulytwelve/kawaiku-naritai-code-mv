# 编码器与位深

## E01 通用默认编码器

**优先级：高。** 目标是让准备好普通软件编码环境的使用者，不必改源代码或拥有 AMD GPU 就能启动渲染。

### 已确认的现状

[`render-film.mjs`](../../production/mv/render-film.mjs) 的 `const encoder` 默认值为 `av1_amf`。只有该值使用 `-quality` / `-b:v`，其他名称一律走 `-preset` / `-crf`。因此任意指定 FFmpeg 编码器并不保证参数适配；换机器后默认路径也依赖 AMD 编码环境。CPU `libx264` 参数路径已经存在，无需重新设计绘图端。

### 实现要求

- [ ] 将默认编码方案改为软件 H.264 `libx264`、8-bit、MP4，保留显式 `--encoder av1_amf` 的兼容路径。默认不进行未经说明的 GPU 探测或切换。
- [ ] 保持已有 `--preset`、`--crf` 语义；明确 CPU 默认值，更新 README 中首选运行示例，让首个示例可在无 AMD 的环境使用。
- [ ] 按实际支持的编码器构造参数。未支持的编码器应明确拒绝，不能继续套用 `libx264` 参数。无需在本任务实现所有厂商的硬件后端。
- [ ] 编码器不存在、无法启动或实际初始化失败时，提供所选 FFmpeg、编码器和关键错误；避免用管道 `EPIPE` 遮盖原因。不能假设任何 FFmpeg 构建都自带 `libx264`。
- [ ] `--dry-run` 和渲染旁车清楚记录选中的编码器、输出像素格式与质量参数。保持 dry-run 不编码视频；若做能力探测，应记录探测范围，不能将编码器列表存在等同于硬件初始化成功。
- [ ] 保留 AMF 已有尺寸填充提示及输出保护；不能改变歌曲/画面映射、场景选择或输出帧数。

### 验收

- 省略 `--encoder` 的已知短区间 dry-run 输出 `libx264`，无 AMF 专用参数；显式 AMF 仍构造对应参数。
- 无 AMD GPU 依赖的环境，使用支持 `libx264` 的 FFmpeg 完成一段短片，ffprobe 确认 H.264、8-bit 4:2:0、指定尺寸和帧率；完整解码该短片。
- 不存在/不支持的编码器参数明确失败，不生成伪成功报告；缺少合法媒体时使用无声或合成输入完成适用验证。
- 编码器选择改变不应改变进入 FFmpeg 前的 Canvas 帧；若调整了绘图或时钟代码，应说明原因并补相应回归。

## E02 可选 10-bit 输出

**优先级：可选新功能，依赖 E01 的编码参数整理。** 不把 10-bit 作为默认分享格式，也不要求所有编码器支持它。

### 已确认的现状

渲染器将 Canvas `data()` 以 `rgba` rawvideo 送入 FFmpeg，输出像素格式固定为 `yuv420p`。目前没有位深选项，也没有编码器与像素格式兼容性校验。

### 实现要求

- [ ] 提供显式位深选择，建议接口为 `--bit-depth 8|10`；默认保持 8。若使用其他接口，文档应同样清晰，且拒绝非法值。
- [ ] 至少实现并实际验证一种软件 10-bit 路线，可考虑 `libx265` 配合 `yuv420p10le`；以目标 FFmpeg 构建真正支持的像素格式为准。不要假定默认 H.264 编码器、AMF 或任意构建都支持目标 10-bit 格式。
- [ ] 对不兼容组合编码前给出明确错误及可用替代组合；用户显式请求 10-bit 时，不允许悄悄退回 8-bit。不要仅改视频标签声称成功。
- [ ] 区分 rawvideo 输入像素格式和编码输出像素格式。改变输出位深时，不得误把仍是 8-bit RGBA 的输入字节流声明为 10-bit，导致数据错位。
- [ ] 保留 SDR / BT.709 的现有意图并核对实际转换与输出标记，不添加 HDR 标记。明确：8-bit Canvas/位图输入转换成 10-bit 编码，不等于恢复原本不存在的色阶细节或构建了端到端 10-bit 制作流程。
- [ ] dry-run 与旁车记录请求位深、输出像素格式、编码器和预期色彩标记；验收记录补实际 ffprobe 结果。像素格式可能比 `bits_per_raw_sample` 更能说明位深，不能只看可能缺失的单一字段。
- [ ] 说明输出兼容性和编码成本，保留 8-bit H.264 为通用默认。不要把 10-bit 成功编码表述成所有播放器均可播放。

### 验收

- 对支持的 8-bit / 10-bit 组合分别规划参数，非法位深及不兼容编码器组合明确失败。
- 在支持目标软件编码器的环境实际输出短片，ffprobe 核对 codec、profile、`pix_fmt`、尺寸、帧率及色彩信息，完整解码通过。
- 使用自产渐变/色块检查转换后的颜色与明显伪影；同时检查实际 MV 的受影响短片。不要把渐变检查解读为所有素材都具备原生 10-bit 精度。
- 未能实际验证 10-bit 路线时，列出具体阻碍，不将开关、命令规划或标签改动当作功能完成。
