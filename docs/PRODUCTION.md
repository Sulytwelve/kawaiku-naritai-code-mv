# 接手、修改与制作

这份文档面向继续维护代码和画面的创作者与 Agent。先读根目录 [README](../README.md) 与 [AGENTS](../AGENTS.md)，了解入口和工程约定，再读 [许可范围](../LICENSING.md) 与 [素材出处](ASSET_ATTRIBUTION.md)。公开仓库提供代码、登记数据、提示词及逐文件允许分发的图片；音乐、字体、混合角色图、原片派生图和部分烘焙输入需要另行合法准备。缺少这些输入时，可以理解和检查代码，但不能据此声称能够重现完整成片。

## 先建立可比较的起点

在工程根目录执行 `npm ci`，再运行 `npm run coverage`。覆盖报告检查轨道时间是否有空洞，不检查文件是否齐全，也不证明人物、动作或声音正确。字体按 README 的环境变量配置；字体变化可能同时改变文字、换行和构图。

接手时记录本次要解决的具体画面，例如“49 秒裤腿与上半身的连接”“电车入场时墙面和人物是否一起移动”。保留修改前的同一小段视频或同一时刻截图，选定一个比较用的输出尺寸、帧率、字体及采样时间。使用新的输出文件名；当前渲染入口会向 FFmpeg 传入覆盖输出的选项。

先确认输入，再开始长渲染：

- `assets/ASSET_INDEX.json` 声明歌曲与主要素材入口。
- `assets/asset-licenses.json` 记录图片的路径、SHA256、出处及分发边界；`commitAllowed` 只对应单个文件。
- `assets/visuals/` 保存人物、合照和背景母图；`assets/runtime/` 保存登记数据、表情补层、合成层与预烘焙画面。
- `assets/third-party-derived/`、音乐、歌词和字体有各自权利条件，不能用相似名称的图片随意顶替。仓库没有包含某张图，并不意味着它是可以删除的输入。

确认自己使用的是当前 `production/mv/` 中的入口和数据。不要将历史片段的画面或时间参数直接当作当前代码的结果。

## 从一个时刻找到真正负责绘制的代码

`production/mv/render-film.mjs` 管理输出时钟、音轨、帧数和 FFmpeg；`production/mv/scene.mjs` 选择轨道、分派场景并合成图层；`production/mv/tracks.json` 保存场景区间、图层和转场。`production/mv/plan.json` 只保留事件 ID 与渲染门控数据，不是详细镜头说明，不能用它替代实际渲染路由。

有两套时间需要区分：输出视频使用歌曲秒数，当前源画面 PTS 为 `clamp(歌曲秒数 - 0.064, 0.129, 252.130)`。整片在 60fps 下输出 15135 帧、252.25 秒。`film-clock.mjs` 是时钟实现，改时序前先读它，不要在多个场景里重复添加或减去偏移。

定位时，先把播放器中的歌曲秒数换算成源 PTS，再在 `tracks.json` 中找到满足 `range[0] <= t < range[1]` 的场景。还要检查同一时刻的 `transitions`，以及场景的 `underlay`：正在看到的画面可能包含下一场、上一场的递归绘制或覆盖在上面的转场。

常见路由如下；最终以 `scene.mjs` 的分派和各 helper 的实际调用为准。

| 轨道字段或内容 | 主要代码与数据 |
| --- | --- |
| `opening`、镜子和结尾 | `opening-scenes.mjs`；`assets/runtime/opening-assets/` |
| `home`、阅读和摄影棚 | `home-scenes.mjs`、`studio-lower-redraw.mjs`；`assets/runtime/home-assets/` |
| `fashion`、服装纸片和结尾队列 | `fashion-scenes.mjs`、`finale-fifo.mjs`；`assets/runtime/fashion/` |
| `photo` | `photo-scenes.mjs`、`photo-room-canvas.mjs`；`assets/runtime/photo-assets/` |
| `magazine` | `magazine-scenes.mjs`、`magazine-smoke-canvas.mjs`；`assets/runtime/magazine/` |
| `social.type = sns-mvp` | 经 `social-mvp-scenes.mjs` 转到 `social-web-film.mjs`；`assets/runtime/social-web-export/` |
| `performance`、`interaction` | `performance-scenes.mjs`、`interaction-scenes.mjs`；同名运行数据目录 |
| `bookshop`、广告 | `bookshop-scenes.mjs`、`ad-code-mvp-scenes.mjs`、`ad-generated-plates.mjs` |
| 全局或局部几何转场 | `core-transition-scenes.mjs` 及其 native helper；对应的轨道与登记 JSON |

不要只搜一遍图片文件名就判断它是否活动。数据里可能保留来源说明或未使用字段；活动调用又可能通过 JSON、序列索引和 helper 动态构造文件名。应顺着一次真实的 `drawScene` 调用读到 `asset`、`loadImage` 或 Canvas 绘制函数。

### 一个最小修改的例子

假设要修改摄影棚人物下半身。先定位歌曲 44–56 秒附近的轨道，沿 `home` 路由读 `home-scenes.mjs`，再检查 `studio-lower-redraw.mjs`。这里的上半身、下半身重绘图、渐变遮罩和共同的相机变换共同构成一个人物。只换一张图而保留不匹配的裁切坐标，可能造成接缝；另外叠一层不随相机移动的裤腿，也会破坏整体运动。

先只改一个输入或一组明确关联的参数。使用相同区间生成短片：

```sh
npm run render -- --output-range 44 56 --width 1280 --fps 60 --encoder libx264 --preset fast --crf 19 --preview-release --out qa/studio-44-56-check.mp4
```

`--output-range` 的端点是歌曲秒数，使用整片的帧时钟；它更适合检查准备合回整片的区间。`--range` 的端点是源 PTS，取样起点不同，不应把两种接口生成的片段混为同一组帧。没有歌曲文件、只检查画面时可加 `--no-audio`。审看范围应包括变化前后留量，而不是只渲染问题出现的一帧。

需要准确定位静帧时，可以在本地检查脚本中调用 `scene.mjs` 导出的 `renderReference(sourcePTS, {width, height, qa: true, watermark: false})`，将返回的 Canvas 编码为 PNG。这个参数是源 PTS，不是播放器歌曲秒数。用于截图的临时脚本与输出放入 `qa/`，不作为正式素材或源码提交。

## 重新生成或替换人物图片

`production/mv/prompts/` 保存实际使用过的创作提示词。它们是描述和参考角色分工的记录，并不是可执行的生图任务；其中的 `image1`、`image2` 指当时配套的姿态与身份参考，公开目录没有承诺包含这些参考输入。接手者需要准备有权使用的图片，并通过自己可用的图像生成或绘画工具完成新图。

一个可靠的替换流程是：

1. 从当前场景的最终输入往回找到人物母图、局部差分和登记数据，确认角色究竟拿着什么、手和道具如何接触、画面裁到哪里。
2. 选择同一身份的稳定参考，明确头发、眼睛、鲸鳍、鲸尾、发饰与服装。姿态参考负责关节、手势、道具、视角与裁切，身份参考负责人物外观；二者不要混写成“随意换一个相似人物”。
3. 阅读对应提示词，按此次镜头说明保留或修改服装、比例、构图和表情。新镜头应有自己的提示词与来源记录。带有其他人物的参考图不能被错误理解成“额外添加这个人物”。
4. 保留新图原件，检查尺寸、透明度和可见边界，再生成实际合成需要的裁切、缩放与局部补层。更新真实被读取的路径和登记坐标。
5. 在角色前一镜、当前镜和后一镜连续审看。脸型、发色、服装、尾巴数量与道具位置都应连贯，而不是每张单图各自好看。

不要通过拉伸整个人物来弥补姿态不对应。母图的尺寸与当前输出尺寸不同是正常的；应按登记的身体框或相机矩阵等比放置。镜内人物、书店握书和摄影棚等场景可能采用专用变换，修改通用 `x/y/w/h` 并不会自动影响所有 helper。

### 透明通道与局部表情

检查真实 alpha，而不是只看图片查看器的背景颜色。在浅色、深色和高饱和底上合成，查看发丝、鲸鳍、尾巴、鞋尖与半透明边缘：背景棋盘、白色剪纸边、黑晕和残余旧人物都可能在动态合成中暴露。透明区携带的 RGB 不能单独证明有烘焙背景，最终要看它与 alpha 一起合成的结果。

可使用安装的 `@napi-rs/canvas` 读取图像、绘制到同尺寸 Canvas，再通过 `getImageData()` 检查 alpha 范围、四角和可见边界。技术检查之后仍需看实际叠底图；“alpha 有零值”不足以证明边缘正常。裁切后必须同步处理登记的原点与矩形，不能只删掉图片四周的透明像素。

局部表情通常应贴到同一个固定身体上，而不是用整张略有漂移的新图替换人物。通用图层的 `patches` 包含可见时间、源矩形与目标矩形；`assets/runtime/opening-assets/expression-registration.json` 还有在母图像素坐标中的专用补层登记。补层先在身体局部坐标对齐，再随身体和相机一起变换；眼睛和嘴单独漂浮在画面坐标中会造成滑动。

检查眨眼或换嘴型前后，身体、头发和道具是否稳定；只保留需要改变的局部。为新文件计算 SHA256，记录从哪张母图或差分提取、如何裁切和放置。运行进程会缓存图片和中间画布，替换文件后应开启新的渲染进程再比较。

图片生成不会自动清除所参考角色的权利条件。大肥鱼、其他 AI 拟人角色、多人合照、原片清理底和道具应按各自来源登记。混合角色图不能因为包含大肥鱼，就整体沿用大肥鱼的 CC BY-NC-SA 4.0。新图与它的裁切、表情、纸片或投影衍生层分别登记；原件有许可记录，不代表所有衍生文件已被自动审核为可提交。

## 设计和修改 Canvas／SVG 动画

主要合成坐标为 960×540，最终 Canvas 根据输出尺寸等比放大。轨迹时间采用绝对源 PTS。位置、透明度与矩阵应由给定时间计算，避免依赖“上一帧向前移动了多少”：同一时间被静帧、区间渲染或递归场景调用时，需要得到相同结果。

在通用图层中，`at()` 读取关键帧；可见区间、`clip`、`clipEllipse`、`affine`、旋转和局部补层会按代码中的顺序组合。改关键帧前检查插值与坐标空间，尤其是数值在哪一个时刻开始生效。专用相机如 `train-entry-camera.mjs` 和队列如 `finale-fifo.mjs` 也有自己的绝对时钟模型，不应再加一套逐帧累积偏移。

`scene.mjs` 中的一般绘制次序是：

1. 保存状态并应用场景相机，绘制 `underlay`。
2. 绘制背景或背景序列，以及各场景的专用 helper。
3. 绘制普通 `layers`、面板入场或社交画面，再绘制 `foregroundLayers`。
4. 场景返回后，整片合成器施加全局转场并绘制它的前景层。

这个次序只是入口层的结构；helper 内仍有独立的遮罩与嵌套图层。镜框要盖住镜中人物的边缘，书与手要按握持关系分层，摄影棚人物和设备要一起受相机控制。每次 `save()` 与 `restore()` 应成对，局部透明度和裁切不能泄漏给后续场景。

制作揭示与擦除效果时，先明确“洞”应穿透哪个完整合成组。`destination-in` 保留遮罩范围，`destination-out` 扣除范围；若在错误的中间层打洞，下面的旧人物或下一场碎片会提前露出。把背景、人物、外框分别处理时，需要检查全遮挡时刻与首尾透明时刻，不能只看最漂亮的中间帧。

SVG 应保留可维护的矢量原件，再按目标像素密度栅格化。`opening-scenes.mjs` 的镜框加载器会在内存中处理特定 `mirror` group，使已有镜面与人物露出；这是针对当前 SVG 结构的适配。换一个 SVG 时，先核对其分组、画布比例和不透明底，不要假设同一正则可以安全处理任何文件。

转场和运动需要覆盖完整行动链：起始姿态、动作、接触或遮挡、结果与下一镜。重点看镜头切换处的位置、尺度、方向与光色连续性。物体从画外离场时用自然裁切，不要因为可见性检测变化而突然换队列或隐藏角色。

## SNS 画面与其他烘焙输入

当前 SNS 主片主要消费已烘焙的屏幕和投影帧。修改 `social-mvp-ui.mjs` 中的帖子文字，并不会自动更新主片里已经生成的 WebP。`social-web-film.mjs` 是当前消费者；它通过时间索引读取 `assets/runtime/social-web-export/`，并另叠手机侧壁和前景拇指。

两个主要清单的约定是：

| 输入 | 消费方式 |
| --- | --- |
| `timeline.json` | 提供 `start`、`end`、`fps`、画布尺寸与 `frames`。消费者按 `floor((t-start)*60+1e-5)` 选择文件名，夹取到有效索引，读取同目录屏幕帧。多个时刻可复用同一帧文件。 |
| `phone-timeline.json` | 提供倾斜手机段的时间和帧文件名；图像从 `phone-projected/` 加载。最终投影帧须与 960×540 的合成设计空间配准。 |
| `sidewall-once.png`、`screen-phone.png` 等 | 手机硬件或屏幕基础输入；前景拇指仍是独立的第三方派生层。 |

清单的 `fps` 是资料，但当前读取器的索引公式明确使用 60。要改变采样率，需要同时修改消费者和重烘焙结果，不能只改一个 JSON 数字。清单中的尺寸还可能描述投影前逻辑屏幕；不能仅凭这些数字缩放已经投影好的整画幅图层。

公开源码没有提供完整的 SNS 网页内容烘焙、逐帧导出与透视批处理脚本，因此不存在一个可以在此承诺的“一条命令重烘焙”流程。`social-mvp-ui.mjs`、`social-ui.mjs` 和手机几何 helper 可以作为实现参考；`preparePhoneHardware()` 可准备部分硬件画布，但不能替代完整的帖子内容和投影序列生成器。

需要改 SNS 时，应取得有权使用的照片和字体，重建原来的逻辑版式、滚动与顶底栏时序，再导出屏幕序列和投影序列，生成与消费者一致的清单。输出应保留真实透明通道、固定投影四边形、侧壁／前板分层和同一个滚动时钟。先验证首末帧、滚动方向、顶部与底部栏是否反复弹出，再连续看整个倾斜手机段。缺少原烘焙输入时，应明确标为无法重现该段，不用低分辨率截图假装等价替代。

同样的原则适用于服装纸片、表情层和封面投影：它们可能是维护输入，不是一次渲染后随手可删的缓存。仅有 JSON 而缺少被引用的图片，通常仍不能渲染。

## 从局部修改到可交付视频

先用 720p60 小范围检查形状、运动和接缝，再按需要检查目标分辨率下的文字、SVG 边缘与透明层。局部看顺之后，重新渲染包含改动的完整段落或整片；相邻镜头的相机、角色与转场可能交叉引用，单个 helper 的孤立样例不能替代集成结果。

动态审看应连续播放完整的受影响行动与转场，必要时逐帧核对问题附近。检查人物与道具接触、身体与补层连接、对象次序、镜头状态、短暂闪白或穿帮、重复帧和不自然停顿。静帧、接触表、解码成功或 `coverage` 为零缺口，各自只能证明有限的事情。

声音检查关注音轨完整性、可播放性、起点、段落同步、结尾与混音异常。当前全片音轨从歌曲零秒开始，画面时钟包含源 PTS 偏移；不能据此给歌词再统一添加 64ms。SRT 本身使用其记录的歌曲时间；区间导出时渲染器会根据音频 seek 调整所写出的外挂字幕。音乐和歌词需要自行具备相应使用依据。字幕源的文件名、合法取值、窗口裁剪与校时约定见 [字幕占位与替换说明](../assets/subtitles/README.md)。

基础技术检查可使用已有 FFmpeg 工具，例如：

```sh
ffprobe -v error -show_streams -show_format -of json qa/studio-44-56-check.mp4
ffmpeg -v error -xerror -i qa/studio-44-56-check.mp4 -f null -
```

核对实际宽高、帧率、帧数、时长、色彩标记和音轨，而不是只读文件名。AMD AV1 编码器对某些尺寸会向 16 的倍数填充；1280×720 与 3840×2160符合这项要求，其他尺寸仍需检查实际输出。片段的帧数按指定区间计算；整片当前应为 15135 帧。输出旁的 `.render.json` 保存渲染参数与代码报告，错误退出、被停止的输出或仍增长的文件不能当作成品。

修改完成后，记录具体改变、实际检查及仍无法验证的部分。运行数据、图片和许可清单要同步；将变更暂存后检查 `git diff --cached --check`、实际文件列表和图片白名单，避免把本地音乐、字体、视频、源资料或机器配置一起提交。

## 接手者需要哪些能力

| 能力 | 能完成什么 |
| --- | --- |
| 阅读代码、JSON 与命令行 | 追踪调用和文件引用、调整关键帧、修复路径、运行覆盖检查与编码、检查技术参数及版本差异。 |
| 视觉理解和动态审看 | 判断姿态、角色一致性、手与物体关系、遮挡、透明边缘、镜头连续性与节奏。这是涉及角色和画面质量的修改所必需的能力。 |
| 图像生成或绘画、透明图层处理 | 产生新角色图、差分或背景并处理真实 alpha。公开代码不自带这项能力；可通过任意合适且具备相应素材权利的外部工具完成。 |
| 持续的工具调用与任务管理 | 等待长渲染、读取进度与错误、复用已完成的输入、追踪多次短片比较，直到拿到可检查的文件。进程启动并不等于制作完成。 |
| 声音播放与声画判断 | 处理配音、音乐、同步或混音修改时确认实际结果；文件存在和流信息不能替代听音。 |

全流程不依赖特定 AI 品牌。只有文本或代码能力的 Agent 可以完成局部程序维护和技术核对，但不应把没有看过的角色图或没有连续播放过的动作宣称为画面验收通过。缺少生图、视觉或播放工具时，应交付已完成的代码与明确的检查边界，并把需要外部能力的步骤留给具备能力的协作者。
